# 🍱 週末作り置き献立（移転しました）

> **このアプリは [stock.yurukichi.com/meal/](https://stock.yurukichi.com/meal/) に移転し、在庫アプリ（[home-stock-manager](https://github.com/matony3/home-stock-manager)）の一部になりました。**
> 今後の開発は home-stock-manager の `meal/` で行います。
> GitHub Pages（`matony3.github.io/kondate/`）は移動用のページです。端末にデータがあれば「データを持って新しい場所へ移動」で引き継げます（`#import=`）。以前の画面は `legacy.html` に残しています。


共働き家庭向けに、**週末にまとめて作る平日（月〜金）の夕食**の献立を提案し、買い物リストまで作るスマホ向け Web アプリです。
レシピ提案には Google AI Studio の **Gemini API** を使います（APIキーがなくても内蔵レシピで動きます）。

## できること

| 画面 | 機能 |
| --- | --- |
| 🗓️ 献立 | 作る曜日を選んで（1日だけ・3日だけ・土日も など）カレンダー形式で表示。一部の日だけ作り直すことも可能（主菜は肉=赤・魚=青、副菜=緑）。冷蔵／冷凍の日を自動で割り当て（タップで切替）。日ごとに「食べる人」を切り替えると分量が自動調整（例：娘が食べない日）。料理ごとに別案・レシピ帳から選択・曜日入れ替え。日曜の**作り置き段取り**も生成 |
| 🛒 買い物 | 1週間分の材料を合算し、カテゴリ別のチェックリストに。**在庫を差し引いた量**を表示（例：豚こま 500g 必要・在庫 300g → 200g）。手動追加、LINE 等に貼れるテキストコピー |
| 📦 在庫 | 家にある食材を量付きで登録。調味料は「常備品」としてワンタップ登録（買い物リストから除外）。在庫の肉・魚は献立提案でも優先 |
| 📚 レシピ帳 | 使ったレシピが自動で残る。★お気に入り／🔁毎週必ず入れる／🚫今後入れない。料理名から AI でレシピ化して登録、手動登録も可 |
| ⚙️ 設定 | Gemini APIキー・モデル、家族構成と量（未就学児 0.5 など）、主菜の好み（鶏もも・むね・ささみ、サバ・ホッケ・鮭…を 👍／👎）、野菜・副菜タイプ（和え物・煮物・サラダ…）・味付け（醤油・味噌・甘酢・マヨ・ピリ辛…）の好み、アレルギー・要望、バックアップ |

- **レシピの選び方**: 「新しいレシピ」「バランス（約4割を過去のレシピから）」「定番中心（過去・お気に入り優先）」から選べます。
- **子ども向け**: 各レシピに未就学児（3〜6歳）向けの取り分けタイミングや味付けの調整が付きます。
- 分量はすべて「大人4人分」で保存し、その日食べる人数に合わせて計算します。

## 使い方

### 1. 公開する（GitHub Pages・無料）

1. このリポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする
2. `main` ブランチにマージすると自動で公開されます（`https://matony3.github.io/kondate/`）
3. スマホで開き、共有メニューから **「ホーム画面に追加」** するとアプリのように使えます

### 2. Gemini APIキーを設定する

1. [Google AI Studio](https://aistudio.google.com/apikey) で APIキーを作成
2. アプリの ⚙️設定 → 「APIキー」に貼り付け →「接続テスト」
3. モデルは既定で `gemini-3.8-flash`（2026年9月GA）。「モデル一覧を取得」で使えるモデルから選べます

> APIキーはその端末のブラウザ内（localStorage）にだけ保存され、Google の API 以外には送信されません。バックアップファイルにも含まれません。

### 3. 毎週の流れ

1. （在庫があれば）📦在庫に登録
2. 🗓️献立 →「献立を作る」。気に入らない料理はタップして「別の案にする」
3. 娘さんが食べない日は、その日の「娘」ボタンをオフ
4. 🛒買い物リストを見ながらチェック
5. 日曜に「段取りを作る」を見ながらまとめて調理

### 4. 家族で同期する（Googleログイン・任意）

Firebase（Google の無料サービス）を使って、夫婦のスマホで献立・買い物リスト（チェック）・在庫・レシピ帳・設定をリアルタイムに共有できます。最初に一度だけ準備が必要です（10〜15分）。

1. [Firebase コンソール](https://console.firebase.google.com/) を開き、「プロジェクトを作成」（名前は `kondate` など。Google アナリティクスはオフで OK）
2. **Authentication** →「始める」→「Sign-in method」→ **Google** を有効にして保存
3. **Authentication** →「設定」→「承認済みドメイン」→「ドメインを追加」で `matony3.github.io` を追加
4. **Firestore Database** →「データベースを作成」→ ロケーション `asia-northeast1（東京）`・**本番環境モード**で作成
5. **Firestore Database** →「ルール」に、このリポジトリの [`firestore.rules`](firestore.rules) の中身を貼り付けて「公開」
6. 歯車 →「プロジェクトの設定」→「マイアプリ」→ ウェブ（`</>`）でアプリを登録し、表示される `firebaseConfig` をコピー
7. コピーした設定を、次のどちらかで登録
   - **おすすめ**：`js/firebase-config.js` に書き込む（家族の端末では貼り付け不要になります）
   - アプリの ⚙️設定 →「家族で同期」に貼り付ける（その端末だけ）

使い方：

1. 1台目で「Googleでログイン」→「家族グループを作る」（その端末のデータがアップロードされます）→ 表示された**招待コード**を家族に伝える
2. 家族の端末で「Googleでログイン」→ 招待コードを入力して「参加」
3. 以後、どちらかが変更すると数秒でもう一方に反映されます。オフライン中の変更は、つながったときに送られます

> Firebase の設定値（apiKey など）は公開されても問題ない情報です。データはセキュリティルールで家族グループのメンバーだけが読み書きできます。
> Gemini の APIキーは既定では同期しません（設定の「APIキーも家族と共有する」をオンにすると共有されます）。
> ホーム画面に追加したアプリでログインがうまくいかない場合は、Safari で開いてログインしてみてください。

## ローカルで動かす

ビルド不要の静的サイトです。

```bash
npm start        # http://localhost:8080 で起動（python3 が必要）
npm test         # 献立・分量・買い物リストのロジックのテスト
```

## 構成

```
index.html            画面の枠
css/style.css         デザイン（ダークモード対応）
js/app.js             画面描画と操作
js/planner.js         献立の組み立て・分量計算・買い物リスト集計
js/prompts.js         Gemini へのプロンプトと応答スキーマ
js/gemini.js          Gemini API クライアント
js/data.js            食材カタログ・内蔵レシピ
js/store.js           端末内への保存
js/sync.js            家族グループの同期（差分の送受信）
js/cloud.js           Firebase（Googleログイン・Firestore）への接続
js/firebase-config.js Firebase の設定
firestore.rules       Firestore のセキュリティルール
sw.js                 オフライン用キャッシュ
```

データは端末内に保存されます。別の端末に移すときは ⚙️設定 の「バックアップを書き出す／読み込む」を使ってください。
